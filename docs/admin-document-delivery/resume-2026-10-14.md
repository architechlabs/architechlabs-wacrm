## Runtime defect found and fixed

Live storage readiness failed despite correct private bucket metadata. A real
workerd probe established that this compatibility runtime rejects
`redirect: "error"` at request construction. This affected storage, Meta media/send
requests and the isolated consumer's private requests; Node-only mocks missed it.

Document-only requests now use `manual` redirects and reject redirect responses
without following or forwarding credentials. Existing ordinary Inbox sends,
webhooks, Resend email and commerce order-confirmation code were not changed.
The admin bridge still uses Node's supported `redirect: "error"` on AWS.

`node scripts/test-document-edge-runtime.mjs` executes the real production modules
in workerd with synthetic service bindings. It verifies private bucket access,
redirect rejection, PDF upload/template send, queue acknowledgement and cleanup.
Seven synthetic requests passed; zero real messages or external provider requests.
